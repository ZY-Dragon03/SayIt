# Design

## Context

基线为已合并 PR #1 的 main commit `d80e13c327ac2a8672e0eee95584cb4333dd422b`。V1 的核验路径已包含安全抓取、来源/元数据检查、正文提取、英文与完整性证据；其后又使用静态出版域名名单作为全文资格门。查询包含宽泛搜索和固定域名提示；最终编辑选择主要由确定性规则完成。

本次动机与必需功能见 proposal；本文件区分冻结产品决定与实现者可选择的技术机制。V1 原文档、49 项验收证据、PR #1 和旧证据分支保持原历史身份。当前主 capability inventory 为空，所以只创建两个聚焦增量 capability；不把旧 change 重新归档作为前置条件。

## Goals / Non-Goals

**Goals:** 让未知出版者凭客观文章证据获得全文资格；让真实模型承担内容语义编辑判断；使每一次交付可从安全核验、语义决定、约束选择追溯到实际正文。

**Non-Goals:** 通用推荐系统、个人政治画像、来源意识形态排行、新插件框架、UI 改版、旧 V1 Issue 重跑、重新解释旧验收或新增付费服务。

## Decisions

### D1. 两种判断的权威分离（冻结产品决定）

文章核验判断“是否安全取得、是否可归属、是否具有合格英文完整正文”；语义编辑判断“是否值得用户今天的阅读位置”。前者由确定性规则负责，后者由真实模型负责。只有前者通过的候选可以进入语义阶段。移除静态域名资格门后仍保留全部原安全、来源、访问与完整性门。

来源核验最少记录结论与客观信号/失败原因，不强制引入数字信誉分；若使用 confidence，其含义只能是出处与完整性证据充分度。已知出版者表只规范显示名称。来源清单不能作为信任提升、拒绝或排序输入。替代方案“扩充名单”不能满足产品目标。

### D2. 宽泛搜索的地位（冻结产品决定）

保存偏好可以生成宽泛搜索和补充提示，但宽泛结果必须具有正常进入候选核验的机会，不能在处理它们之前用静态站点候选耗尽全部预算。未知出版者是否存在以候选运行前生产来源/名称列表快照为准；验收 fixture 或证据文档中的域名引用不构成生产来源政策。

验收保留查询、来源、候选决策与语义状态，至少一个真实网络运行需要列表外出版者完成全文核验或语义决定。宽泛搜索只返回已知出版者时，仍是一次合法运行，但不能充当这项 V1.1 能力的 PASS 证据。

### D3. 有界语义输入和受约束输出（冻结产品决定）

Agent 接收固定候选集合的结构元数据及有界内容证据。每篇至少包括稳定候选标识、标题、可核对来源、文章长度/估值、时间（未知明确空缺）、已提取正文的短表示、去重关系，以及用户偏好与已经选入/已有文章的必要摘要。文章文本是非权威数据，不能作为改变系统指令的指令来源。完整正文无需发送给模型；有界表示必须足以区分普通事实复述、解释和独立观点。

版本化结果对每个输入候选作明确语义决定，包含主题适配、编辑价值、分析深度、新颖性、与已有文章重叠、观点贡献及简短依据；可使用枚举或有限分值。语义批准是新增文章入选的必要条件，不等于最终交付；确定性约束检查仍可缩减批准集合。模型不得修改 URL、publisher、canonical、access、全文状态、词数/时长/难度或 Issue 完成状态。

缺项、未知/重复候选、未知版本、非法值不是成功响应。字段类型、具体版本字符串、上下文长度、批量上限、超时与 JSON 验证机制属于实现决定，必须在实现计划固定并可从 trace 验证，不能放宽上述权威边界。

### D4. 语义服务依赖和失败（冻结产品决定）

默认复用用户已有 SayIt 模型配置。V1.1 不启用确定性策展自动降级；缺少配置、调用失败或无效结构均记录语义失败，不交付本次未经批准的新文章。旧文章、Daily Issue、进度和已合法缓存内容不受影响。暂时故障可以遵守 V1 的有界重试；永久配置缺失应明确显示需要可用语义配置。没有新的无限重试或定时补跑规则。

Provider/模型 ID、契约版本、调用结果和已脱敏 request/response 摘要必须能核对真实模型执行；不得保存 API key。真实调用证明 Agent 做过判断，输入内容证据和理由共同证明它判断了什么。只将确定性分数包装成 JSON 不满足契约。

### D5. 观点、主题与最终选择（冻结产品决定）

保留 V1 对副本、转载、镜像和近重复的内容判据。相同事件的独立报道/分析继续有资格共同入选；Agent 用实际内容增量判断阅读价值，不以政治方向过滤。主题适配由语义阶段判断；关键词可以提供线索，不能独自决定相关性或强制排除语义上合适的候选。FKGL、200 words/min、篇数、时长区间与履约由确定性软件计算。

语义阶段不能靠“推荐 COMPLETE”弥补实际短缺，也不能为了数量填入否决的文章。一次没有可批准新增文章的运行可以有明确短缺；若语义能力实际不可用，则记录能力失败。对于已有 PARTIAL/COMPLETE Issue，原 V1 合并、抑制定时发现和 Regenerate 规则不变；既有 V1 文章无须补跑语义阶段。

### D6. 最小理由持久化（冻结产品决定）

新交付文章保留一条紧凑理由、贡献类型、语义契约/决定关联。理由可在已有详情或运行 trace 显示，无需另建 UI 面板。历史 V1 数据缺少理由时应正常读取，不伪造“Agent 已判断”的历史。来源事实与模型理由分开保留，理由不能变成来源证据。

### Engineering Decisions

实现者负责模型调用适配方式、JSON schema/类型、内容摘录与批处理方式、错误分类、日志结构、持久化向后兼容、查询配额和 final selection 算法。优先扩展现有 provider、fetch、Reader service 和验证基础设施。不得让 PM 的产品冻结变成特定类名/API/数据库方案的冻结。实现前用短 Implementation Plan 与 Feasibility Gate 证明现有提供商支持有界语义调用、响应可验证且无需新付费承诺；技术选择与限额需写入新的工程记录，不改本契约含义。

## Risks / Trade-offs

- 来源名单移除增加未知站点输入 → 保留并证明全部客观完整性/来源核验，未知且可疑候选必须 fail closed。
- 语义调用产生延迟与已有模型用量 → 限定候选/内容输入并复用现有服务；具体限额由工程计划记录，不增加付费订阅。
- 模型判断存在波动 → 用清楚的同主题对照、实际输入与决定证据验收，不能只观察 HTTP 成功；不得为获得 PASS 悄改用例。
- 有界摘录可能遗漏深层内容 → 实现选取可解释的正文表示；记录实际输入，避免从标题臆造质量。
- 线上来源可能消失或限流 → 可更换满足相同冻结条件的真实来源并记录尝试；网络不可达记录 blocker/NOT-RUN，不用 mock 冒充实时运行。

## Migration Plan

在从当前 main 派生的独立分支实施。新字段必须兼容 V1 已存数据；旧记录可缺少 Agent 理由。最终集成候选运行正常工程套件、10 项新 PAT 和本变更 acceptance-plan 中受影响 V1 观察。新 evidence 目录记录候选 SHA，不修改旧 V1 evidence。通过后开新 PR，main 与 PR #1 不改写。

## Open Questions

无须 Product Owner 进一步裁决的产品问题。工程实现细节由实现角色解决；若遇到不可避免的新付费承诺或客观核验无法成立，才升级为真实阻塞。
