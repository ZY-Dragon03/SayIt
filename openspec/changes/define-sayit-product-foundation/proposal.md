## Why

SayIt 要解决的不是“查一个词”或“改一条语法”，而是用户已经有一个模糊、破碎或带噪声的英语想法，却不知道自然英语会如何表达。现有反向词典通常只做“描述 -> 单词”，而通用聊天机器人又要求更长的交互；SayIt 需要把“messy thought -> intended meaning -> natural expression”定义成一个极轻量、可重复使用的 Expression Retrieval Engine。

现在先明确产品边界、结果契约和最小技术基础，可以避免 MVP 漂移成词典、翻译器、语法教学平台或聊天应用，并为后续实现提供可测试的行为规格。

## What Changes

- 定义 SayIt 的核心 JTBD、主要用户、日常使用循环和产品原则。
- 定义桌面优先、响应式、键盘优先的单输入面板与紧凑结果面板。
- 定义从破碎英语、模糊描述、部分句子、拼写错误和语法噪声中推断意图，并选择单词、搭配、短语、词块、短语动词、习语、句型或完整句的行为。
- 定义噪声处理规则：静默归一化明显 typo/键盘错误，区分语法噪声与真正值得学习的表达缺口。
- 定义结构化模型输出、服务端 API 代理、模型提供商抽象、错误处理和安全边界。
- 定义本地优先的表达保存能力，不引入账户、远程数据库或跨设备同步。
- 定义性能、可访问性、测试、部署和未来扩展点，并记录应明确排除的复杂性。
- 不实现生产代码；本变更只交付产品、UX、AI 契约和技术规格。

## Capabilities

### New Capabilities

- `expression-retrieval`: 将带噪声的英语输入转换为意图、最佳自然表达、相关替代表达和可直接使用的自然句子，并返回可稳定渲染的结构化结果。
- `local-expression-memory`: 允许用户在本地保存、查看和取消保存有价值的表达，不依赖登录或远程同步。

### Modified Capabilities

无。当前项目没有既有能力规格。

## Impact

- 将来会新增 React/TypeScript 客户端、极小的服务端 API 代理、模型提供商适配层、结构化响应校验和本地持久化模块。
- DeepSeek 只作为初始提供商，不进入浏览器代码；API 密钥和模型调用必须留在服务端。
- 需要新增产品行为、模型契约、错误场景、键盘交互和本地存储的自动化测试。
- 初始部署目标是一个静态前端加一个无状态 API 服务；不引入认证、用户数据库、分析系统或后台任务。
